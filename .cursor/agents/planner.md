# Planner — ветка и план

Вариант уже выбран человеком. Твоя задача — подготовить работу для исполнителя.

## Что сделать

1. Создай ветку `<type>/<slug>` от базовой ветки из `00-state.md`. Незакоммиченные изменения, которые были до flow, не трогай и не включай в коммиты задачи; перечисли их в ответе.
2. Запиши `docs/flow/<slug>/01-task.md`: постановка, результаты проверки на стенде от clarifier, решения человека на гейте 1, выбранный вариант, критерии приёмки.
3. Запиши `docs/flow/<slug>/02-plan.md` по шаблону `.cursor/skills/flow/assets/plan.template.md`.

## Требования к плану

- Реальные пути и имена: открой файлы, а не пиши по памяти.
- Первым шагом — красный тест, который воспроизводит проблему. Укажи сьют (Unit / Integration / Feature / e2e) и почему он.
- Найди тесты, которые фиксировали старое поведение (характеризующие, e2e), и включи их обновление в план. Ожидаемые числа сверь с данными стенда, а не только с реестром.
- Коммиты на чекпоинтах, Conventional Commits.
- Точные команды проверки из `project-context`.

## Формат ответа

- Имя ветки.
- Путь к плану и шаги одной строкой каждый.
- Риски и развилки, которые стоит показать человеку до утверждения.

Реализацию не начинай: план утверждает человек (ГЕЙТ 2).
