**Область:** текущий незакоммиченный дифф, изменённых файлов: 3 — `e2e/tests/Browser/VacanciesTest.php`, `www/local/modules/ws.vacancies/lib/Repository/VacancyRepository.php`, `www/local/modules/ws.vacancies/lib/Service/VacancyService.php`. Для проверки вызовов и контрактов также прочитаны `AGENTS.md`, `docs/bugfix_plan.md`, `docs/legacy/seed.php`, `.settings.php` и `install/index.php` модуля, `VacancyStatTable`, `VacancyStatRepository`, `VacancyFilterDto`, компонент `legacy:vacancies`, его AJAX-адаптер и публичные точки входа `/vacancies/`. ## Проверено и чисто

- Глобальная сортировка: `Reference` регистрируется до `setOrder()`, а `ORDER BY STAT.VIEWS DESC, ID DESC` применяется до `LIMIT/OFFSET`; PHP-сортировка среза удалена. Файлы: `VacancyRepository.php:137-151`, `VacancyService.php:31-39`.
- ORM-связь: `this.ID = ref.VACANCY_ID` корректна; `VACANCY_ID` — первичный ключ, поэтому JOIN не размножает вакансии. В текущем ядре `Reference` по умолчанию использует `LEFT JOIN`, следовательно отсутствие строки статистики не исключает вакансию. Файлы: `VacancyRepository.php:599-613`, `VacancyStatTable.php:20-24`.
- Tie-break: при равных `VIEWS` производственный порядок детерминирован через `ID DESC`; замечание выше относится только к отсутствию регрессионного теста. Файл: `VacancyService.php:33`.
- SQLi: пользовательский `sort` нормализуется белым списком в `VacancyFilterDto`, затем переводится в фиксированный массив через `match`; имя поля и направление из HTTP-запроса в `setOrder()` не попадают. Runtime-отношение и условие JOIN состоят из констант. Файлы: `VacancyFilterDto.php:27-33`, `VacancyService.php:31-37`, `VacancyRepository.php:555-577`.
- XSS: дифф не добавляет пользовательские данные в HTML, URL, JavaScript или атрибуты; значение `sort` используется только как нормализованный код режима выборки.
- CSRF и права: изменённый путь — публичное чтение списка и не выполняет мутаций; новых отключений фильтров, GET-мутаций или обходов прав дифф не добавляет. Известные дефекты соседних путей учтены в реестре как баг №11 и здесь не дублируются.
- Архитектура D7: запрос и runtime-связь находятся в Repository, выбор режима сортировки — в Service, HTTP-компонент остаётся тонким; в изменённых PHP-файлах есть `declare(strict_types=1)`, прямого доступа к superglobals и SQL вне Repository нет.
- Счётчик и пагинация: count-запрос остаётся без JOIN, а отношение статистики 1:1 не меняет число строк list-запроса; `total`, `totalPages` и текущая страница сохраняют прежний контракт.
- Статическая проверка: `php -l` для всех трёх изменённых файлов и `git diff --check` завершились без ошибок.

## Решения (заполняет человек)
